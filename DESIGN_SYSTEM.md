# Dream Wedding Builder Design System

## Status
ACTIVE — Hallmark + Hostile UX Redesign Authority

## Product Position
Dream Wedding Builder is a premium bridal planning intelligence system, not a generic mood-board app, dashboard builder, or Pinterest clone.

The interface should feel like a luxury planner notebook and intelligent bridal concierge: calm, editorial, grounded, and planner-grade.

## Core Visual Direction
- Luxury planner notebook
- Intelligent bridal concierge
- Editorial wedding packet
- Soft planning desk / planner table
- Constraint-first working brief

## Palette
- Ivory: primary page atmosphere
- Linen: primary card/paper surface
- Champagne: premium accent and soft emphasis
- Sage: calm planning/status accent
- Rose: romantic accent, used sparingly
- Charcoal: authority, copy, primary CTA

## Typography
- Serif headlines should feel editorial and bridal, not default SaaS.
- Sans copy should stay clear and operational.
- Use generous line-height for calm planning readability.
- Avoid overusing all-caps badges as the only hierarchy.

## Layout Principles
- Fewer generic rounded card grids.
- More editorial feature bands, planner notes, spec sheets, packet previews, and staged workflow sections.
- Preserve explicit Step 0, Step 1, Step 2, etc. because the workflow needs deterministic sequencing.
- One dominant active planning action per major surface.
- Unknown/incomplete states should feel calm, not deficient.

## Trust Markers
Use designed trust markers near the top of planning surfaces:
- Seeded examples only
- No live availability claimed
- Verify before booking
- Confidence labels included
- Planner packet records assumptions

## Component Language
Preferred:
- planner packet previews
- planning assumptions
- marginal notes
- annotated planner cards
- structured spec sheets
- staged workflow bands
- calm empty states

Avoid:
- repetitive generic SaaS card grids
- too many pill CTAs
- dashboard-heavy density
- unstyled disclaimers that read as fine print
- fake live-data confidence

## CTA Hierarchy
Homepage:
1. Primary: Start the Planning Reality Check
2. Secondary: Ask the Planner Brain
3. Tertiary/contextual: Photos Lab

Build page:
1. Primary: Start Step 0: Reality Check
2. Secondary: Ask the Planner Brain
3. Packet access remains available after planning state exists

## Mobile Rule
Mobile should have only one bottom fixed system: the navigation bar. Do not add competing sticky estimate widgets on mobile.
